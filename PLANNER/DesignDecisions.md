# Decisions and rationale

Status: design decisions for implementation, subject to the explicit runtime gates. Source IDs refer to [RESEARCH](RESEARCH.md).

| ID | Decision | Why / rejected alternative | Consequence and reopen trigger |
|---|---|---|---|
| D01 | Manual Colab → immutable ZIP → local website. | Fits 4–5 hackathon videos and avoids building GPU hosting, tunnels and queues. | Website cannot run new visual inference. Reopen only after prototype validation if unattended uploads become a real requirement. |
| D02 | Measure timestamps/signals first; VLM describes bounded visual evidence; Cerebras reasons over the shared evidence ledger. | Numerical timing belongs to media tools. A VLM-only score obscures causes and invents precise times. | Validators reject out-of-evidence claims. A language model never owns final numerical retention. |
| D03 | Primary Qwen3.5-27B BF16, 80GB-class GPU; explicit Qwen3.5-9B BF16 fallback on 40GB. | Preserve unquantized weights while acknowledging actual storage/VRAM needs. Official model IDs and shard sizes supersede earlier attachment estimates. [S01–S05] | Lower-capacity results are labelled and independently gated. Lack of 80GB allocation prevents the primary profile; no retry can solve capacity. |
| D04 | Qwen3-VL-32B-Instruct is a contingency experiment, not the baseline; LLaVA-OneVision-2-8B-Instruct is a deferred challenger. | Qwen3.5 integrates visual processing and the chosen Transformers class. A 32B model is not a low-memory escape route. LLaVA's distinct code/processor would add a second runtime to maintain. [S06–S07] | Only compare on the frozen clip rubric if baseline fails a specific task; changing models creates a new profile. Model family names or general leaderboards do not prove project quality. |
| D05 | No quantization, CPU/disk offload, FlashAttention compilation, torch.compile, vLLM or SGLang in default execution. | Most benefit is unnecessary for batch size one; extra kernels/offload create failure surfaces. BF16 weights plus bounded clips simplify diagnosis. | Reference DeltaNet can be slow; a measured throughput failure may justify a separately pinned optimized-kernel profile. No silent enablement. [S03] |
| D06 | Isolated ASR/embedding, VLM, OCR and media environments, controlled by notebook subprocesses. | WhisperX 3.8.6 and Transformers 5.7.0 impose incompatible Hub requirements; process exit releases GPU allocations reliably. [S08–S11] | Stage files are the interface. Do not fix one stage by upgrading every environment. |
| D07 | Shot-aware bounded sampling plus uniform baseline coverage. | Only sampling suspicious moments creates confirmation bias; full dense video prompts waste memory. | Every analysed clip records sampled PTS and unknown intervals. Refine selected regions at a higher density. |
| D08 | Local evidence store in SQLite + files, no vector DB or multi-agent framework. | Four or five videos are small; embeddings can be searched in memory. Simpler persistence makes imports and lineage auditable. | Add scalable infrastructure only after a real concurrency/size requirement. |
| D09 | Retention scenario and observed diagnostic evidence are distinct. | No calibrated labels currently exist. Public replay peaks do not establish abandonment. [S17–S19] | Show assumptions next to rates. Actual audience-accuracy claims remain blocked without authentic labels. |
| D10 | Fixed issue ontology and bounded two-pass reasoning, no autonomous critic/director loop. | A first proposal plus deterministic validation is auditable; unlimited self-critique creates latency without reliable correction. | At most one schema repair, then partial result. Reviewer rejection is recorded, not repeatedly prompted away. |
| D11 | Externally edited media is reanalysed as a new asset. | A suggested fix is not evidence that the video improved; cuts can remove context and moves can break continuity. | Hypothetical comparison and fresh diagnosis are separate modes; actual viewer uplift remains unknown. |
| D12 | English/Hindi source text preserved; transcript correction versioned. | Romanisation, code mixing and alignment failures can create false repetition/pace findings. | Missing word times downgrade precision. Translation is a display aid, never a replacement for source evidence. |
| D13 | Functional review workspace first; UI/UX polish later. | Judge value comes from traceable findings, not motion. User explicitly deferred UI work. | Preserve the supplied visual system as design authority without building it during planning. |
| D14 | Two categories initially; presets alter retrieval/context, not arbitrary retention penalties. | A static educational diagram can be useful while the same unchanging visual may fail a product demonstration. | Add vlogs only after category-specific annotations; avoid universal cut-every-eight-seconds rules. |
| D15 | Cerebras model ID is runtime configuration, selected from account-accessible catalogue; do not assume “OSS20B” is hosted. | Public catalogue and account entitlements change. Text functions need a working strict-output endpoint, not a guessed name. [S16] | A single capability probe selects a recorded available model; no API key belongs in browser, prompts, package or documents. Offline evidence review remains usable. |

## Model comparison policy

Primary selection is a feasibility and integration decision, not a claim that Qwen universally beats LLaVA. The current model cards do not evaluate Hindi creator retention defects. The official Qwen3.5-27B model card reports broad video/OCR benchmarks; these cannot establish temporal accuracy or edit quality here. Use six preselected clips: small Hindi text, mixed-language explanation, static but useful lecture, fast cuts, irrelevant B-roll, delayed title payoff. Evaluate evidence precision, false alarms, structured-output success, peak VRAM and runtime. No challenger may enter the demo merely because its overall benchmark is higher.

The earlier proposal contains unsupported shortcuts: `Qwen3.5-VL-7B` is not the selected official checkpoint; “fits easily” ignores activations and video tokens; scene length >8s is not a defect by itself; exact frame number = time × average FPS is wrong for variable-frame-rate footage; a text-only prompt containing no images cannot inspect video. The implementation must follow the corrected profiles, real multimodal input and PTS contracts here.

## UI interpretation — constraints only

Preserve the supplied dark amber glass palette and warm surfaces. Canonical tokens are background #0B0B0C, canvas #1C1C1E, card #242426, primary text #F5F2EE, secondary #A9A5A0, amber #D98A1E. Hero coral uses the guide's named tokens #FF7B7B and #E8506A; its differing sample gradient is illustrative, not a second authority. Fonts planned: Inter for interface, Source Serif 4 for restrained headings, Noto Sans Devanagari fallback for Hindi. Bundle font assets locally for offline demo, subject to license verification during implementation.

At desktop size use a video/transcript area, evidence/issue panel and full-width timeline; chat opens as a panel rather than replacing the workspace. A compact dock can map to Projects, Review, Edit plan and Evaluation. The guide's Team/Profile/credits/voice examples do not create product requirements. Use text labels or accessible names, visible keyboard focus, 44px targets, tested contrast and patterns/labels alongside colour. Essential timestamps cannot use low-contrast tertiary text. Reduced motion is respected; no animation is needed for any delivery gate.

Retention chart y-axis is percentage and title includes “Estimated — uncalibrated”; risk chart has its own 0–100 risk axis. Never combine them under one ambiguous score. Display a source/timing badge on each finding, `visual analysis incomplete` when relevant, and a visible assumptions button beside scenario metrics. Layout mockups and detailed interaction styling are a later task.
